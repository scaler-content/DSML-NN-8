Optimisers: how a network finds its way down the loss hill

Training a network means searching for the weights with the lowest loss, and plain gradient descent does that slowly. Follow Aria, a NovaMart delivery rider, as her route to the hub improves with Momentum, RMSprop, Adam and learning rate decay.

The problem: NovaMart’s demand segments

NovaMart is a quick-commerce grocery startup. Its delivery-ops team wants to group neighbourhoods into three demand segments — Light, Regular and Heavy — based on order frequency, basket size and delivery distance, so the right number of riders can be assigned to each zone.

A first look at the data shows the segments twisting around each other in a way no straight line can separate. The team decides a deep neural network is needed instead of a simple linear model.

Aria and the hill

Running alongside the business problem is a second, smaller story. Aria, a NovaMart delivery rider, must find the fastest route down a hilly part of the city to reach the delivery hub. Her search for the quickest way downhill is a close cousin of what a network’s optimiser does when it searches for the point of lowest loss. We will return to her ride with every new idea.

import numpy as np
import matplotlib.pyplot as plt
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
import tensorflow as tf
from tensorflow.keras import Sequential
from tensorflow.keras.layers import Dense

np.random.seed(7)
tf.random.set_seed(7)

# Simulated neighbourhood demand data: two engineered features, non-linear boundary
X, y = make_moons(n_samples=1500, noise=0.25, random_state=7)

plt.figure(figsize=(5,4))
plt.scatter(X[:,0], X[:,1], c=y, cmap="coolwarm", s=10)
plt.title("NovaMart neighbourhoods: two demand segments")
plt.xlabel("feature 1 (standardised order frequency)")
plt.ylabel("feature 2 (standardised basket size)")
plt.show()

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=7)
scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)
X_test = scaler.transform(X_test)

def build_model():
    model = Sequential([
        Dense(16, activation="relu"),
        Dense(16, activation="relu"),
        Dense(1, activation="sigmoid")
    ])
    return model

Training with vanilla mini-batch gradient descent

Let W be the collection of the network’s weights, b its biases, and L(W, b) the loss — a single number telling us how wrong the network’s predictions currently are. Vanilla gradient descent updates the weights like this:

W←W−η⋅∂L∂W

The gradient points in the direction the loss increases fastest, so we move the opposite way to reduce it. The learning rate η is a small positive number that controls how large that step is.

How many examples per update?

“Mini-batch” names one of three ways to decide how much data each weight update looks at.

Batch

Uses the entire dataset for every update.

Mini-batch

Uses a small group of examples for every update.

Stochastic (SGD)

Updates after a single example: the noisiest, but fastest to start.

Observe

After 15 epochs the loss is still high and barely moving. Left to train for a few hundred epochs it does eventually settle — but NovaMart’s real order data has millions of rows, and waiting hundreds of epochs is not realistic before every rider-allocation decision.

Why is training so slow?

Picture Aria again. The loss surface is the hill she is riding down, her position is the current weights W, and each gradient calculation tells her the steepest direction downhill from where she is standing right now — not the best overall route to the hub.

If the hill is a long, narrow valley — steep on the sides, gently sloping along the floor — her bike keeps swerving from one wall to the other instead of rolling smoothly along the floor toward the hub. Each mini-batch also gives the network a slightly different, noisy read of “which way is downhill”, so the weights zig-zag the way Aria’s bike does. That zig-zagging is why so many epochs are needed.

Smoothing the ride: exponential moving average

Instead of reacting fully to every noisy reading, Aria could blend her current direction with the direction she was already travelling in. That blending idea is an Exponential Moving Average (EMA):

Vt=β⋅Vt−1+(1−β)⋅gt

Here t is the current step. A β close to 1 means Aria trusts her established direction more and reacts less to each bump in the road.

Gradient descent with momentum

Momentum applies the EMA idea directly to the gradient, then uses the smoothed value to update the weights:

VdW=β⋅VdW+(1−β)⋅∂L∂WW←W−η⋅VdW
Aria’s version

A bicycle picks up speed rolling downhill and doesn’t change direction over every small bump. Momentum lets the optimiser build up speed along the valley floor while cancelling out the side-to-side swerving.

Show the Keras code
model_momentum = build_model()
model_momentum.compile(optimizer=tf.keras.optimizers.SGD(learning_rate=0.05, momentum=0.9),
                        loss="binary_crossentropy")

history_momentum = model_momentum.fit(X_train, y_train, validation_data=(X_test, y_test),
                                       epochs=15, batch_size=64, verbose=0)

plt.plot(history_vanilla.history["loss"], label="vanilla GD")
plt.plot(history_momentum.history["loss"], label="GD + momentum")
plt.title("Vanilla GD vs Momentum: 15 epochs")
plt.xlabel("epoch"); plt.ylabel("loss"); plt.legend(); plt.show()
Observe

With the same 15 epochs and the same learning rate, momentum reaches a noticeably lower loss than vanilla gradient descent. Aria’s bike is now rolling smoothly down the valley floor instead of bouncing between the walls.

RMSprop: smoothing the size of gradients

Momentum speeds Aria up, but on a very steep-sided valley she can still overshoot and wobble. RMSprop takes a different approach: instead of smoothing the direction, it smooths the size of past gradients and uses that to shrink the step in directions that have been consistently steep.

SdW=β2⋅SdW+(1−β2)⋅(∂L∂W)2W←W−η⋅∂L/∂WSdW+ε

Dividing by √S automatically takes smaller steps in directions that have been consistently steep and larger steps in directions that have been consistently gentle.

Aria’s version

She brakes automatically on the steep cross-slope and pedals harder along the gentle straight.

Adam: Momentum and RMSprop together

Adam (Adaptive Moment Estimation) combines Momentum’s smoothed direction VdW with RMSprop’s smoothed step-size control SdW. Because both start at zero, they are biased toward zero in the earliest steps, so Adam corrects for this before using them:

V^dW=VdW1−β1tS^dW=SdW1−β2tW←W−η⋅V^dWS^dW+ε
Aria’s version

She gets both benefits at once: a smoothed sense of direction, and automatic braking on the steep parts of the hill.

Why the bias correction?

An EMA that starts at zero underestimates the true value early on. Dividing by 1 − βt lifts it back up, and the correction fades as t grows.

Spot the gap in an AI’s explanation

An AI assistant, asked to explain Adam in one line, wrote this:

“Adam is the best optimiser because it removes the need to choose a learning rate at all — it figures out the entire step size automatically.”

It sounds confident, but it is not quite right. Check it against the update rule and find what η still does there.

What the update rule says

In W ← W − η · V̂ / (√Ŝ + ε), the learning rate η still multiplies the whole step, so it still has to be chosen (the Keras run above sets 0.01). Adam adapts direction and relative step size using its two running averages; it does not remove η. “Best” is also a claim the lecture does not make.

A more accurate one-liner: Adam smooths each weight’s direction and scales its step by recent gradient size, but the learning rate η still sets the overall step scale.

Treat any AI-generated technical explanation as a first draft to verify against the actual formula, not a final answer.

Learning rate decay

Even with Adam, a fixed learning rate can be too large to settle precisely once training is close to the minimum. Aria is nearly at the hub, but her steps are still large enough to overshoot it. Learning rate decay shrinks η gradually as training progresses:

ηepoch=η01+r0⋅epoch

The notebook run used η₀ = 0.01, r0 = 0.05 and 15 epochs, which are this widget’s starting values.

Show the PyTorch code
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import TensorDataset, DataLoader
# matplotlib.pyplot and numpy are already imported in previous cells and are available.

# 1. PyTorch Model Definition
class NovaMartModel(nn.Module):
    def __init__(self, input_features):
        super(NovaMartModel, self).__init__()
        self.layer1 = nn.Linear(input_features, 16)
        self.relu1 = nn.ReLU()
        self.layer2 = nn.Linear(16, 16)
        self.relu2 = nn.ReLU()
        self.output_layer = nn.Linear(16, 1)
        self.sigmoid = nn.Sigmoid()

    def forward(self, x):
        x = self.relu1(self.layer1(x))
        x = self.relu2(self.layer2(x))
        x = self.sigmoid(self.output_layer(x))
        return x

# 2. Data Preparation for PyTorch
# X_train, y_train, X_test, y_test are numpy arrays from previous cells.
X_train_tensor = torch.tensor(X_train, dtype=torch.float32)
y_train_tensor = torch.tensor(y_train, dtype=torch.float32).unsqueeze(1) # unsqueeze for BCELoss
X_test_tensor = torch.tensor(X_test, dtype=torch.float32)
y_test_tensor = torch.tensor(y_test, dtype=torch.float32).unsqueeze(1)

batch_size = 64
train_dataset = TensorDataset(X_train_tensor, y_train_tensor)
test_dataset = TensorDataset(X_test_tensor, y_test_tensor)

train_loader = DataLoader(train_dataset, batch_size=batch_size, shuffle=True)
test_loader = DataLoader(test_dataset, batch_size=batch_size, shuffle=False)

# 3. PyTorch Model Initialization and Training Setup
input_features = X_train.shape[1] # Get input dimensions from the prepared data
model_adam_decay_torch = NovaMartModel(input_features)

initial_lr = 0.01
optimizer = optim.Adam(model_adam_decay_torch.parameters(), lr=initial_lr, betas=(0.9, 0.999))
criterion = nn.BCELoss() # Binary Cross Entropy Loss

# 4. Learning Rate Scheduler for PyTorch
decay_rate_r0 = 0.05
def pytorch_lr_lambda(epoch):
    # The original formula is lr_epoch = initial_lr / (1 + r0 * epoch)
    # For LambdaLR, this function returns a multiplicative factor for the learning rate.
    # So, the factor is 1 / (1 + r0 * epoch)
    return 1.0 / (1.0 + decay_rate_r0 * epoch)

lr_scheduler = optim.lr_scheduler.LambdaLR(optimizer, lr_lambda=pytorch_lr_lambda)

# 5. Training Loop
epochs = 15
history_decay_torch_loss = []
history_decay_torch_val_loss = []

for epoch in range(epochs):
    # Training phase
    model_adam_decay_torch.train()
    running_loss = 0.0
    for inputs, labels in train_loader:
        optimizer.zero_grad()
        outputs = model_adam_decay_torch(inputs)
        loss = criterion(outputs, labels)
        loss.backward()
        optimizer.step()
        running_loss += loss.item() * inputs.size(0)

    epoch_train_loss = running_loss / len(train_dataset)
    history_decay_torch_loss.append(epoch_train_loss)

    # Validation phase (optional, but good for tracking)
    model_adam_decay_torch.eval()
    val_loss = 0.0
    with torch.no_grad():
        for inputs, labels in test_loader:
            outputs = model_adam_decay_torch(inputs)
            loss = criterion(outputs, labels)
            val_loss += loss.item() * inputs.size(0)

    epoch_val_loss = val_loss / len(test_dataset)
    history_decay_torch_val_loss.append(epoch_val_loss)

    # Update learning rate after each epoch
    lr_scheduler.step()

# 6. Plotting Results
plt.plot(history_adam.history["loss"], label="adam (TF)") # Use existing TF history for comparison
plt.plot(history_decay_torch_loss, label="adam + LR decay (PyTorch)")
plt.title("Adam vs Adam with Learning Rate Decay (PyTorch)")
plt.xlabel("epoch"); plt.ylabel("loss"); plt.legend(); plt.show()

Playground: all four optimisers on one hill

This is Aria’s hill: a narrow valley with the loss L = 0.05 w1² + 5 w2², gentle along w1 and steep along w2. Every optimiser starts from the same point (4, 4) and aims for the hub at (0, 0). Change the sliders and switch routes on or off to see how each path responds.

Show the reference implementation (Python)
import numpy as np

# A narrow valley-shaped loss surface: steep in one direction, gentle in the other
def loss_surface(w1, w2):
    return 0.05 * w1**2 + 5 * w2**2

def grad_surface(w1, w2):
    return np.array([0.10 * w1, 10 * w2])

def run_optimiser(kind, lr, beta1, beta2, steps=40, start=np.array([4.0, 4.0])):
    w = start.copy()
    v = np.zeros(2)
    s = np.zeros(2)
    eps = 1e-8
    path = [w.copy()]
    for t in range(1, steps + 1):
        g = grad_surface(*w)
        if kind == "vanilla":
            w = w - lr * g
        elif kind == "momentum":
            v = beta1 * v + (1 - beta1) * g
            w = w - lr * v
        elif kind == "rmsprop":
            s = beta2 * s + (1 - beta2) * (g ** 2)
            w = w - lr * g / (np.sqrt(s) + eps)
        elif kind == "adam":
            v = beta1 * v + (1 - beta1) * g
            s = beta2 * s + (1 - beta2) * (g ** 2)
            v_hat = v / (1 - beta1 ** t)
            s_hat = s / (1 - beta2 ** t)
            w = w - lr * v_hat / (np.sqrt(s_hat) + eps)
        path.append(w.copy())
    return np.array(path)

Key takeaways

  • Vanilla GDSlow and noisy, because each step reacts fully to a single, noisy gradient reading.
  • EMASmooths a noisy sequence by blending each new reading with the running average.
  • MomentumApplies that smoothing to the gradient direction, speeding up convergence along gentle slopes.
  • RMSpropSmooths the squared gradient and shrinks steps in steep or noisy directions.
  • AdamCombines Momentum and RMSprop, with bias correction for the earliest steps.
  • LR decayShrinks the step size over time so the optimiser can settle precisely near the minimum.
  • PlaygroundAll four optimisers trace different paths down the same loss surface from the same starting point.
